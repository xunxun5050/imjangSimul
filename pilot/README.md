# 실거래 데이터 파일럿 — 노원구(11350)

가상 매물 생성기를 **실제 단지명 + 실거래 중앙값** 기반으로 바꾸는 최소 파이프라인입니다.

```
국토부 실거래가 API ──▶ collect_listings.py ──▶ listings.json ──▶ 게임에서 불러오기
```

---

## 1. 준비

1. [공공데이터포털](https://www.data.go.kr)에서 **국토교통부_아파트 매매 실거래가 상세 자료** 활용신청
2. 승인 후 마이페이지에서 **일반 인증키(Decoding)** 복사
3. 승인 반영까지 보통 몇 분~1시간 걸립니다. 바로 401이 나와도 정상입니다.

## 2. 실행

```bash
export MOLIT_KEY="발급받은_디코딩_서비스키"
python3 collect_listings.py --lawd 11350 --months 12 --out listings.json
```

의존성 없습니다. 표준 라이브러리만 씁니다.

```
[1/2] 실거래 수집: 11350 최근 12개월
  202503   312건
  ...
      유효 거래 3,104건
[2/2] 단지·평형 그룹핑
완료 → listings.json  (단지 187개 / 평형 402종)
```

| 옵션 | 기본 | 설명 |
|---|---|---|
| `--lawd` | 11350 | 법정동코드 앞 5자리 |
| `--months` | 12 | 최근 N개월 |
| `--min-deals` | 3 | 평형당 최소 거래건수. 낮추면 표본이 얇은 단지가 섞입니다 |

## 3. 게임에 넣기

`imjang-simulator.html`을 열면 첫 화면 맨 위에 **매물 데이터** 블록이 생겼습니다. 여기서 `listings.json`을 선택하면 상태 문구가 `노원구 실거래 기반 · 단지 N개`로 바뀌고, 그때부터 나오는 매물이 전부 실제 단지가 됩니다. 파일을 안 넣으면 기존 가상 생성 모드 그대로 돌아갑니다.

배포용으로 고정하려면 HTML 안의 이 슬롯에 JSON을 통째로 붙여넣으면 됩니다.

```html
<script id="listings-data" type="application/json">null</script>
```

먼저 감을 보려면 `listings.sample.json`을 넣어보세요. **구조 확인용 합성 데이터라 가격은 실제가 아닙니다.** 불러오면 화면에 빨간색으로 경고가 뜹니다.

## 3-1. K-apt 단지정보 보강 (선택)

세대수·주차대수·인접역·난방방식을 실데이터로 채웁니다. 활용신청 2건이 더 필요합니다.

- 국토교통부_공동주택 **단지 목록**제공 서비스 (data.go.kr/data/15057332)
- 국토교통부_공동주택 **기본 정보**제공 서비스 (data.go.kr/data/15058453)

```bash
export KAPT_KEY="$MOLIT_KEY"      # 같은 계정이면 같은 키
python3 enrich_kapt.py --in listings.json --out listings.json
```

```
[1/3] 대상 단지 187개 (노원구)
[2/3] K-apt 단지 목록 조회
      경로 확정 [list] .../AptListService3/getSigunguAptList
      K-apt 등록 단지 312개
[3/3] 기본정보·상세정보 조회
      경로 확정 [bass] .../AptBasisInfoServiceV3/getAphusBassInfoV3
완료 → listings.json
  매칭 168/187 (90%) · 그중 퍼지매칭 23건
```

보강되면 게임 리포트가 이렇게 바뀝니다.

```
+ 상계역까지 걸어서 5분. 지하철 접근은 확실합니다.     ← subwayStation / kaptdWtimesub
+ 지역난방이라 겨울 난방비가 예측 가능합니다.          ← codeHeatNm
- 세대당 주차 0.83대. 밤 10시 넘으면 이중주차입니다.   ← kaptdPcnt + kaptdPcntu
```

**주의할 점**

- 두 서비스는 엔드포인트 버전이 여러 번 바뀐 이력이 있습니다. 스크립트가 후보 경로를 순서대로 찔러보고 통한 걸 캐시하지만, 전부 실패하면 포털 활용가이드에서 현재 경로를 확인해 `LIST_BASES` / `INFO_BASES` 상수를 고치세요.
- 매칭은 단지명 문자열 비교입니다. `matchScore`가 1.0 미만인 건은 눈으로 확인하세요. 매칭률이 60% 밑이면 `--threshold 0.75`로 낮춰보세요.
- **총층은 K-apt에 없습니다.** 실거래 관측 최대층 + 2로 추정하고 `totalFloorsEstimated: true`를 남깁니다. 게임에서는 층 표기에 `*`가 붙습니다. 정확히 하려면 건축물대장 표제부 `grndFlrCnt`를 붙여야 합니다.
- 응답은 `.kapt_cache.json`에 캐시됩니다. 다시 돌려도 API를 재호출하지 않습니다. 갱신하려면 이 파일을 지우세요.

## 4. 호가 환산

API는 실거래가만 주므로 호가는 이렇게 만듭니다.

```
호가 = 최근 N개월 동일 평형 실거래 중앙값
     × askPremium(기본 1.05)
     × 층보정(저층 0.92 / 탑층 0.96 / 로열층 1.04)
     × marketIdx(게임 내 시장 이벤트)
     × U(0.97, 1.03)
```

`askPremium`은 `listings.json`의 `meta.askPremium`에서 바꿉니다. 상승장이면 1.08까지, 하락장이면 1.02 근처가 현실적입니다.

## 5. 다른 구로 확장

`collect_listings.py`의 `DONG_META`에 법정동을 추가하면 됩니다. 이 표가 기존 `REGIONS` 레코드를 대체합니다.

```python
"11710": {  # 송파구
    "_zone": "서울", "_gu": "송파구",
    "잠실동": {"x": 11, "y": -7, "t": 1.00, "edu": 4, "inf": 5, "env": 4, "fut": 4},
    ...
}
```

- `x`, `y` — 서울시청 기준 km (동쪽 +x, 북쪽 +y). 통근시간 계산에 쓰입니다.
- `edu`/`inf`/`env`/`fut` — 1~5 주관 점수. 여기가 유일하게 손으로 채우는 부분입니다.
- 메타에 없는 법정동의 거래는 조용히 버려집니다.

## 6. 알아둘 것

- **취소 거래**(`해제여부 = O`)는 걸러냅니다. 안 거르면 신고가가 오염됩니다.
- **최근 1~2개월은 표본이 얇습니다.** 실거래 신고 기한이 30일이라 아직 안 들어온 거래가 있습니다.
- **전용면적 기준**입니다. 84㎡가 게임에서 25평으로 표시되는 건 정상입니다. 기존 공급면적 표기(84㎡=34평)와 다릅니다.
- **세대수는 `enrich_kapt.py`로 채웁니다.** 총층은 어느 API에도 없어 추정값입니다(3-1 참고).
- **향·수리상태·누수·세입자·소음은 계속 랜덤**입니다. 임장 가야만 아는 정보라서 그대로 두는 게 맞습니다.
- 공공데이터는 원칙적으로 상업적 이용이 가능하지만 데이터셋별로 제한될 수 있으니 재배포 전 이용 조건을 확인하세요.

## 7. 스모크 테스트 결과

합성 샘플(단지 10개 / 평형 28종)로 자동 플레이 40회를 돌린 결과입니다.

```
연소득 7,500 / 현금 3억 / 생애최초 / 강남역 근무 / 6개월
→ 계약 39회, 미계약 1회, 등장 단지 10/10
예시: 노원구 상계동 5억 5,300만원 (실거래 8건 중앙값 5억 2,800만원)
      대출 3억 3,180만원 · 월 162만원 · 만족도 52
```

계약 성공률이 높게 나오는 건 노원구 가격대가 이 예산에 넉넉해서입니다. 명세서 11절의 `계약 성공률 기저(0.86)`나 `heat 계수`로 조이거나, 예산을 낮춰 잡으면 됩니다.
